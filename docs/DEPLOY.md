# Deploying the web surface

The repository is a library and a CLI; `webapp/` adds a thin HTTP shell so the
project can be looked at without installing anything. It is deliberately small -
three JSON endpoints and one server-rendered page - because it is meant to run on
a free tier.

## What it serves

| Route | Purpose |
|---|---|
| `/` | Server-rendered audit of the three bundled scenarios |
| `/api/audit/{scenario}` | The full audit report as JSON |
| `/api/scenarios` | Scenario ids, goals and node counts |
| `/api/tools` | The tool surface with schemas and risk classes |
| `/healthz` | Liveness probe used by the platform |
| `/docs` | OpenAPI UI, generated by FastAPI |

Everything is computed on the deterministic mock device, so the deployment needs
no emulator, no Android SDK and no GPU - just Python and Pillow.

## Render (free plan)

The repository ships a `render.yaml` blueprint, so the deploy is one click after
the repository is connected:

1. Sign in at [render.com](https://render.com) with GitHub.
2. **New -> Blueprint**, pick `MVCODE`, and apply. Render reads `render.yaml`,
   creates the `droidcode` web service on the free plan, and builds it.
3. First build takes a few minutes (`pip install` plus a small wheel build);
   after that the service is live at `https://<service>.render.app`.

Without the blueprint, create a **Web Service** manually and set:

```
Runtime:       Python 3
Build command: pip install -r requirements.txt && pip install -e .
Start command: uvicorn webapp.app:app --host 0.0.0.0 --port $PORT
Health check:  /healthz
```

### What the free plan means here

- The instance **sleeps after ~15 minutes** of inactivity and cold-starts in
  roughly 50 seconds. Fine for a demo, wrong for a service.
- **512 MB RAM.** The audit pipeline is pure Python plus one small Pillow image,
  so a report costs a few megabytes - there is headroom.
- Free instances share CPU; an audit of one screen takes well under a second on
  the mock device.

## Anywhere else

The app is a standard ASGI application, so nothing here is Render-specific:

```bash
pip install -r requirements.txt && pip install -e .
uvicorn webapp.app:app --host 0.0.0.0 --port 8000
```

A `Dockerfile` is not required for Render's Python runtime, but the same command
pair works unchanged in a container, on Fly.io, or behind any reverse proxy.

## What is not deployed

The adb backend needs a device and a network path to it, so it is not part of the
hosted surface. Running against real hardware stays local:

```bash
droidcode audit --adb --serial emulator-5554 --tokens evals/tokens.json
```
